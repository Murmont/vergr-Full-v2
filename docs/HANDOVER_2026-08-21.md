## 4. ⚠ What you must RECHECK before trusting it

I do not do visual testing; the founder does. Everything below is **code-verified
only** unless stated. Treat it as unproven.

### Highest risk, verify before the next store build

**`isShrinkResources = true`** (`src-tauri/gen/android/app/build.gradle.kts:154`).
Resource shrinking compiles clean and breaks at **runtime**. I checked the one
pattern the shrinker cannot see through (`getIdentifier` appears nowhere in the
Kotlin, verified) and Tauri's web bundle lives in `assets/` which shrinking does
not touch. **But the only real proof is a built artifact plus a smoke test.** If
anything in the native shell renders wrong after the next build, revert this line
first. It is a size optimisation, not a fix; it is not worth a broken release.

**Bitmap decode rewrite** (`VergrMessagingService.kt`). Compile-verified with
`./gradlew :app:compileUniversalReleaseKotlin`, never run. Needs a real push
notification **with a photo** and **with a sender avatar** to confirm images still
render and are not blank or over-compressed. Constants are `PHOTO_MAX_DIM = 1024`
and `AVATAR_MAX_DIM = 512`.

**Orientation opt-out** on `ScannerActivity` / `ArCameraActivity`. Needs a tablet
or unfolded foldable to verify. Nobody has tested it. Also note the opt-out
**stops working at targetSdk 37**, so those two screens need a real landscape
layout before that bump.

## 6. ⚠⚠ Two systemic risks, neither fixed

**The entire native Android app is untracked in git.** `.gitignore:12` ignores
`src-tauri/gen`, which contains 43 hand-written Kotlin files (MainActivity 47KB,
ArCameraActivity 68KB, the whole camera, call, billing and media stack), the
`AndroidManifest.xml`, and `app/build.gradle.kts`. Verified per file with
`git ls-files --error-unmatch`.

This violates a hard rule already in CLAUDE.md, and it is the same failure class
that caused the 1.0.193 web-mode APK disaster. It is **not** safely regenerable:
`tauri android init` would overwrite every custom file. One `git clean -fdx` or one
branch checkout and it is gone. **Founder decision, item 1 above.**

**Nothing is committed.** Last commit is `ed9291a`, which predates every change
described here. The working tree carries weeks of uncommitted work from multiple
sessions. The web changes are deployed to hosting straight from the tree.

## 7. Rules that will bite you if you skip them

From `CLAUDE.md`, the ones most likely to catch a new session:

- **Never remove a feature, screen, route, button or link without explicit
  permission.** Broken screen means build it or stub "Coming soon". Ask if unsure.
- **Never use em dashes** in any output: chat, commits, docs, code comments.
- **Tournaments do not exist.** Retired, unrouted, content deleted. The huge
  tournaments section in CLAUDE.md is dead-code documentation, not a build queue.
- **Nobody can withdraw anything, ever.** No convert, no withdraw, no gem
  transfer. Gems are deleted. Coins are a revocable licence, not stored value.
- **Revenue share is the only model, 50% to 80% by lifetime gross earned.** The
  flat 10% fee and the VP commission ladder are both dead. Grep for the WORD in
  copy, not just the function name; that mistake left five live screens selling a
  dead model.
- **Never paywall access to money already owed.** Earnings, memberships, payout
  setup and statements are free for every account.
- **Verify the ARTIFACT, never the command you typed**, for any Android build.
- **Batch native work.** One APK at the end, and do not build until the founder
  says go. Do not run unwatched heavy jobs on his machine.
- **Deploy it yourself.** "Build passes" is invisible to the user;
  `firebase deploy --only hosting` is what makes it real.
- Mixed CRLF/LF in this repo silently breaks multi-line patch anchors. Check line
  endings before a multi-line edit.

## 8. Useful facts discovered this session

- **The Rust build is wired into `merge*JniLibFolders`, NOT into Kotlin
  compilation** (`buildSrc/.../RustPlugin.kt:60,78`). So
  `./gradlew :app:compileUniversalReleaseKotlin` with `ANDROID_HOME=C:\Android\sdk`
  is a ~40 second syntax check, not a 20 minute cargo build. Use it.
- The variant task is `compileUniversalReleaseKotlin`, not `compileReleaseKotlin`
  (that name is ambiguous and errors).
- `public/version.json` at 1.0.199 is **not drift**. It describes the last
  published sideload APK on the CDN with that artifact's own size and sha256.
  1.0.200 and 1.0.201 were store builds.
- The local Firebase CLI OAuth token carries only `cloud-platform`, `firebase` and
  `userinfo.email`. **No `androidpublisher` scope**, so Play Console cannot be read
  from the CLI without a service-account key.
- Play account migration off Murmont LLC is researched and recorded in CLAUDE.md.
  Short version: the D-U-N-S cannot be edited, so it needs a **new payments
  profile** linked to the same developer account, **no app transfer**, and the EIN
  gates the whole chain. Do not start it half-way.
